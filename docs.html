ImageGenerate

Gere imagens por IA sem sair do lugar: prompt + contexto + referências → imagem + log. Três interfaces, um mesmo núcleo: CLI no terminal, GUI desktop (Tkinter) e Web no navegador (React + FastAPI). Junto vem o StoryGenerate: transforma storyboards em roteiro + narração em áudio, com um player para ouvir lendo o roteiro.

Por que três interfaces?O núcleo de geração (run_generation() em image_generate.py) é compartilhado. Cada interface é só uma “casca” diferente sobre o mesmo pipeline — então tudo que a GUI faz, o CLI também faz (paridade garantida).

Instalação

Pré-requisitos

  • Python 3.10+ (GUI usa Tkinter, que já vem na maioria das distros)
  • Node 18+ só para compilar o frontend web
  • Chave de API do provedor (OPENROUTER_API_KEY) — ou use --dry-run grátis, sem chave
pip install cryptography fastapi uvicorn   # cofre de chaves + backend web
cd web/frontend && npm install && npm run build && cd ../..
Por quê compilar?O server.py serve o web/frontend/dist/ (build), não o src/. Editou o frontend? Rode npm run build de novo e recarregue — sem reiniciar o servidor. Para hot reload, use npm run dev (porta 5173, com proxy de /api para a 8000).

Launcher Linux (ícone no dock)

bash install.sh                # pergunta se instala também o StoryGenerate [s/N]
bash install.sh --with-story   # instala os dois sem perguntar (--no-story: só o ImageGenerate)
# depois: tecla Super → ImageGenerate / StoryGenerate → Enter (abra pelo launcher, não pelo terminal)
Sem sudoO instalador é por usuário (~/.local) e recusa rodar como root: com sudo o HOME vira /root e o atalho iria para o menu do root. Ele só escreve lançadores e ícones — nunca mexe em ~/.config/image_generate/ (configurações e chaves). Pode rodar de novo quantas vezes quiser.

Início rápido

# Grátis, sem chave: gera um placeholder local
python3 image_generate.py --prompt "teste" --dry-run

# GUI desktop
python3 image_generate.py --gui

# Web (em outro terminal, após o build do frontend)
python3 web/server.py   # http://127.0.0.1:8000

# Com chave (OpenRouter — veja “Conta OpenRouter” abaixo)
export OPENROUTER_API_KEY="sk-or-..."
python3 image_generate.py --prompt "uma arara voando" --prop 16:9 --resolution 1K

Conta OpenRouter

Tutorial básico para sair do --dry-run e gerar de verdade. São 3 passos: conta → chave → modelo.

1. Criar a conta

  1. Abra openrouter.ai e clique em Sign Up / Sign In (vale conta Google ou e-mail).
  2. Adicione créditos no dashboard (Billing) — os modelos pagos descontam daí; modelos marcados free não custam nada.
Por quê OpenRouter?Um gateway único para centenas de modelos com a mesma API. O app já manda os headers que ele recomenda (HTTP-Referer, X-Title) — você só entra com a chave.

2. Criar a API key

  1. No dashboard, abra Keys e clique em Create.
  2. Dê um nome (ex.: ImageGenerate) e, se quiser, um limite de gasto — bom para não estourar crédito sem querer.
  3. Copie na hora: o valor completo (sk-or-…) aparece uma única vez e não pode ser recuperado depois. Perdeu? Apague e crie outra.
  4. Cole no app — aba Model (marque remember me para guardar no cofre) ou via export OPENROUTER_API_KEY="sk-or-…" / --api-key.

3. Escolher o modelo

  1. Abra o catálogo em openrouter.ai/models e filtre por image (ou busque pelo nome).
  2. Copie o slug — o identificador no formato autor/nome, ex.: meta/muse-image (é o padrão do app).
  3. Cole no campo Model (aba Model) ou passe --model autor/nome. Confira preço por imagem e tamanho de contexto na página do modelo.
  4. Para o Summary model (só escreve 1 frase no log), escolha um modelo grátis/pequeno — ele não afeta a qualidade da imagem.
Teste baratoValide chave + modelo com --dry-run primeiro (não gasta nada) e só depois rode a geração real.

CLI (terminal)

A forma completa e scriptável. Tudo que a GUI/Web fazem passa por aqui.

Exemplos

python3 image_generate.py --prompt "um farol à noite" --prop 21:9 --resolution 2K
python3 image_generate.py --prompt-file ideia.md --prompt "variação:" --context-dir ./docs --memory-dir ./refs
python3 image_generate.py --prompt "ok" --dry-run --api-key "sk-or-..." --remember-key  # guarda no cofre + teste grátis
python3 image_generate.py --provider openrouter --forget-key   # apaga a chave guardada
python3 image_generate.py --list-log                           # mostra o histórico CSV
python3 image_generate.py --analyse ./A --analyse ./B          # compara pastas (aba Analyse no terminal)
python3 image_generate.py --analyse ./A --analyse ./B --choose 1:2 --choose 3:1   # copia as escolhidas + relatório
Guardar chave--remember-key precisa de --api-key (ou da variável de ambiente) junto: ele criptografa e salva antes de gerar. O exemplo acima combina com --dry-run para validar tudo sem gastar.

Ctrl+C cancela: aborta as conexões, apaga arquivos parciais, não registra nada no log.

GUI (desktop)

Janela Tkinter em 4 abas fixas (Generate, Model, Dir, Analyse) mais a aba Injection, que só aparece quando é útil. Abra com python3 image_generate.py --gui. O botão ? no canto do cabeçalho abre esta documentação.

  • Dicas flutuantes: passe o mouse sobre os campos — cada um explica o que faz.
  • Preview de proporção: o ⓘ ao lado de “Aspect” desenha o retângulo da proporção escolhida.

  • Quantidade (×N ao lado do Generate): naturais 1–30; acima de 1 abre confirmação avisando que cada imagem pode somar custo. Acima de 10, o pedido é dividido em chamadas de no máximo 10 imagens (limite do OpenRouter/OpenAI por chamada) — você recebe todas.
  • Lista do log (Summary): da requisição mais nova para a mais velha (padrão), atualizada a cada imagem de um lote. Ordenar e filtrar: clique no cabeçalho de uma coluna para ordenar (de novo inverte; ▲/▼ indica), respeitando números e datas. Botão direito no cabeçalho abre o filtro estilo planilha: ordenar ▲/▼, “Contains…”, valores com contagem para marcar/desmarcar, All/None, Clear filter. Colunas filtradas ganham ▾; o rodapé mostra “N of M” e o custo só das linhas visíveis; Clear filters volta tudo. A ordenação fica salva; os filtros valem na sessão. Botão direito → Use prompt recarrega o prompt daquela linha; o menu fecha ao clicar fora ou com Esc.

Aba Analyse (comparar e escolher)

Para escolher as melhores imagens entre várias pastas (modelos, tentativas, prompts diferentes) sem mexer nos originais:

  1. Add folder… — adicione pelo menos 1 pasta (sem limite); cada pasta vira uma coluna (✕ remove). As pastas ficam salvas no config.
  2. Linha N = a N-ésima imagem mais recente de cada pasta (data de modificação do arquivo); pasta com menos imagens mostra “—”. Order ⇅ inverte e alinha pela mais antiga (seleções mantidas; se duas caírem na mesma linha, uma é descartada com aviso).
  3. Clique seleciona (verde) — uma por linha: clicar em outra da mesma linha troca; clicar de novo desmarca. Duplo clique abre a imagem em tamanho real; com o mouse parado sobre uma imagem aparece uma prévia grande (o maior tamanho que cabe ao lado do cursor — até ~75% da largura e ~85% da altura da tela, sem ampliar além do original; sempre dentro da tela e sem cobrir o cursor) com nome, pasta, data e tamanho — some ao tirar o mouse, clicar ou rolar.
  4. Zoom − / Zoom + (canto direito): miniaturas de 100 a 480 px (100, 150, 220, 320, 480), mantendo as seleções. Rolagem com a roda do mouse (Shift + roda = horizontal).
  5. O rodapé mostra linhas, selecionadas, linhas sem escolha e, por pasta, imagens e selecionadas.
  6. Choose copia as escolhidas para <Chosen dir>/<data_hora>/ (vazio = <pasta-mãe do Output dir>/chosen, ao lado das pastas comparadas), como <linha>_<pasta>_<arquivo>, com report.md e report.csv.

O relatório traz as pastas comparadas (imagens, escolhidas, % das escolhas), a tabela das escolhidas e, por imagem: origem, contra quais imagens foi escolhida, prompt completo, provedor/modelo, seed, proporção, resolução, custo e data — lidos do log_image_generate.csv da pasta ou de até 2 pastas acima (imagens movidas para subpastas continuam encontradas). Miniaturas via ImageMagick/ffmpeg, com cache em ~/.cache/image_generate/thumbs.

CLI equivalente--analyse A --analyse B imprime a tabela; --choose LINHA:COLUNA (repetível, 1 por linha) copia; --oldest-first e --chosen-dir também existem. --gui --analyse A --analyse B abre a aba já com as pastas.

Dynamic (uma subpasta por geração)

Abaixo de cada pasta (Output, Context, Memory) há o checkbox Dynamic, habilitado só quando n > 1 (padrão: desmarcado). Marcado, aparecem as caixas Start (primeira subpasta, natural ≥ 1, padrão 1), Range (última subpasta, natural > Start, obrigatória) e Batch (quantas gerações seguidas ficam em cada subpasta, natural ≥ 1, padrão 1). As gerações usam, em ordem, <pasta>/<Start> … <pasta>/<Range> e voltam ao Start: com n=10, Context Start 1/Range 10 e Output Start 1/Range 5, a geração 6 lê ctx/6 e salva em out/1. Com Batch > 1 as gerações ficam agrupadas: Start 2, Range 12, Batch 3 → gerações 1–3 na pasta 2, 4–6 na 3, 7–9 na 4…; passando do Range, volta ao Start. O Start serve para retomar um lote sem refazer as primeiras pastas (ex.: Memory Start 2, Range 12, n=11 → pastas 2…12). Pastas sem Dynamic ficam fixas. Subpastas de contexto/memória precisam existir (validado antes de gerar, nada é gasto); as de saída são criadas, cada uma com seu próprio CSV. Com seed definida, a geração i usa seed + i − 1.

CLI equivalente--count 11 --dynamic-memory 12 --dynamic-memory-start 2 (também --dynamic-output[-start|-batch], --dynamic-context[-start|-batch] e --dynamic-memory-batch). Na web, os mesmos campos ficam na aba Dir.

Aba Injection (variáveis no prompt)

Quando a quantidade é > 1 e o prompt contém variáveis {{qualquer texto}}, aparece a aba Injection (título em amarelo). Nela há uma tabela com uma linha por geração e uma coluna por variável — preencha o valor de cada variável em cada geração:

prompt: "crie uma imagem de um {{pessoa}} com um {{objeto}}."   ×3

| pessoa | objeto   |
1| menino | sorvete  |
2| cavalo | capacete |
3| carro  | palhaço  |

Isso gera 3 requisições: “…um menino com um sorvete”, “…um cavalo com um capacete” e “…um carro com um palhaço”.

  • Célula vazia repete o valor da linha de cima; na primeira linha, usa o próprio nome da variável.
  • Tabela totalmente vazia → alerta e a geração não começa.
  • A aba aparece/some sozinha conforme o prompt e a quantidade; cada célula vazia preenchida com repetição é resolvida na hora do Generate.
CLI equivalenteNa linha de comando use --inject 'pessoa=menino,objeto=sorvete' — uma opção por geração (a quantidade vira o número de opções). Célula ausente/vazia repete a linha anterior ou o nome da variável. Se o prompt tem {{variáveis}}, --count > 1 sem --inject é erro. Na web, surge a aba Injection na barra de abas do topo (mesma condição: quantidade > 1 e variáveis no prompt).

As preferências da GUI — incluindo o último prompt, as pastas da Analyse e o Chosen dir — são salvas em config.json no cofre (ao gerar e ao fechar) e restauradas na próxima abertura. Precedência: padrões < config.json < flags explícitas.

Web (navegador)

Mesmo núcleo, visual moderno escuro. Sirva o build e abra http://127.0.0.1:8000.

A web tem as mesmas funções dos dois apps desktop: o seletor ImageGenerate | StoryGenerate no topo troca de app (/#story abre direto no StoryGenerate) e as configurações são os mesmos config.json / story_config.json — o que muda num aparece no outro.

Aba Generate

  • Composer: caixa grande de prompt com a toolbar em pílulas (Ratio, Res, Fmt, dry-run) e botões Cancel / Generate. O Ratio tem preview da proporção no ⓘ.
  • Status ao vivo: cronômetro + estado via SSE (idle, generating, done, cancelled, error) e botão 🔔/🔕 do som.
  • Histórico: tabela do CSV com totais; clicar numa linha recarrega o prompt dela (branch de variação sem sobrescrever nada; o botão direito na linha também tem Use prompt). Como na GUI, clique no cabeçalho ordena (▲/▼, a ordem fica salva) e o botão direito no cabeçalho abre o filtro estilo planilha (ordenar, Contains…, marcar valores, All/None, Clear filter); ▾ marca colunas filtradas e Clear filters no rodapé limpa tudo.
  • Modal de sucesso: ao receber a imagem, abre um aviso moderno com selo ✓, som de alerta (chime sintetizado via Web Audio, sem arquivo), preview, caminho completo com botão Copy path e Open full size. Erro toca um tom grave; cancelamento não toca nada.
  • Quantidade (×N ao lado do Generate): naturais 1–30; acima de 1 pede confirmação no navegador destacando o custo adicional.
Por que o som às vezes não toca?Navegadores bloqueiam áudio sem gesto do usuário. O contexto de áudio é criado no clique do Generate — se a aba estiver mutada ou o autoplay bloqueado, o modal aparece normalmente, só sem som.

Aba Model

A web usa o mesmo config.json da GUI e salva mesclando (só a opção alterada): pastas da Analyse, Chosen dir, ordenação da lista e o último prompt são compartilhados entre as duas, e nada que a outra guardou é apagado.

Provedor, modelo de imagem, modelo de resumo e chave. O status mostra (configured via vault/env) em verde ou (not configured) em vermelho — mesma informação do backend, só colorida para leitura rápida.

Aba Dir + folder picker

Cada pasta tem input (digitar/colar) + botão Browse…, que abre um modal navegando nas pastas reais da máquina (o servidor é local): caminho atual, ⬆ Up, ⌂ Home, lista de subpastas, criar nova pasta e Use this folder. O modal abre na pasta digitada; se ela não existir, avisa e abre na pasta-mãe existente mais próxima. Abaixo de cada pasta há o mesmo Dynamic da GUI (Start, Range, Batch; habilitado só com quantidade > 1).

Limite do navegadorO seletor nativo de pastas do browser não entrega o caminho real ao servidor por segurança — por isso o picker navega no servidor via /api/browse em vez de <input type=file>.

Aba Analyse

A mesma Analyse da GUI: Add folder… (folder picker), pastas como chips com ✕, Order ⇅ (mais novas/mais velhas primeiro, mantendo as escolhas), Clear selection, Refresh e Zoom −/+. Clique numa miniatura para escolhê-la na linha (borda verde, uma por linha); duplo clique abre em tamanho real. Parar o mouse sobre uma imagem mostra a prévia grande ao lado do cursor. Choose copia as escolhidas para <Chosen dir>/<data_hora>/ (vazio = chosen/ na pasta-mãe do Output dir) com report.md + report.csv, e o aviso final tem links para os relatórios e Open folder.

StoryGenerate na web

Selecione StoryGenerate no topo. As mesmas quatro abas do app desktop (detalhes):

  • Generate: pastas com Browse…, idioma, Writer, Duration, dry-run, redo existing; Generate stories (pede confirmação quando não é dry-run), Cancel, Retry failed (n); linha de status generating… x/y done (n failed) | status: passo (N s). O log tem as mesmas colunas, falhas em vermelho, ordenação/filtro no cabeçalho e o menu do botão direito na linha (Copy row, Open in Player, Open folder, Delete audio only…, Delete script + audio…, Show error, Retry this storyboard); duplo clique abre no Player (ou mostra o erro).
  • Model: Writer model (cadeia com ;), TTS model, chave OpenRouter com remember me / Forget (mesmo cofre).
  • Voices: até 5 voice ids + rótulos e Check voices.
  • Player: lista das histórias, storyboard e roteiro com divisórias arrastáveis; na imagem, roda = zoom no ponto do cursor (até 3× o original), arrastar = mover, botão direito = padrão. O áudio toca no navegador (com busca), a cena atual fica destacada, clique numa cena pula até ela; mesmos controles e atalhos (Espaço, ←/→, ↑/↓).

StoryGenerate (storyboard → história narrada)

story_generate.py transforma cada imagem de uma pasta de storyboards numa história escrita e narrada. Abra com python3 story_generate.py --gui (ou pelo launcher) — ou na web. O botão ? do cabeçalho abre esta seção.

  1. Roteirista (modelo de chat com visão no OpenRouter; padrão google/gemini-3.7-flash): lê os quadros da esquerda para a direita e de cima para baixo, escreve uma cena por quadro com transições, dá um título curto e escolhe a voz mais adequada entre até 5 vozes do Fish Audio.
  2. Narração (Fish Audio via OpenRouter): lê cada cena com a voz escolhida; as cenas viram um único audio.wav com uma pausa curta entre elas — por isso o player sabe onde cada cena começa.
  3. Saída: pasta <título>/ com storyboard.png (cópia), roteiro.md, audio.wav e story.json (metadados + tempos das cenas), mais o log_story_generate.csv na pasta de saída.
Uma chave sóRoteirista e narração usam a mesma chave OpenRouter do ImageGenerate (cofre compartilhado). Não precisa de conta no Fish Audio: o voice id é o código na URL da voz (fish.audio/m/<id>).

Configurações (pastas, modelos, idioma, estilo, duração, vozes) ficam em story_config.json, salvas ao gerar e ao fechar. Os storyboards originais nunca são alterados — só copiados.

Roteirista: estilo, duração, fallback e nível de pensamento

  • Estilo (dropdown Writer): Descritivo conta o que cada quadro mostra, fiel às imagens; Narrativo foca nas transições — cada cena começa explicando por que/como o personagem saiu do quadro anterior e chegou a este (ex.: a menina limpava o sapato e agora anda na rua — para onde vai?), sem contradizer nenhum quadro.
  • Duração alvo (Duration, vazio = automático; 90, 1:30, 2m): convertida em palavras por voz, com a velocidade de fala medida nas suas histórias anteriores (vozes leem em ritmos bem diferentes). Espere cerca de ±15%.
  • Cadeia de fallback: no Writer model, separe modelos com ; — ex. qwen/qwen3.8-27b:free;google/gemini-3.7-flash. Cada modelo tem direito às suas novas tentativas; se falhar (limite, erro, resposta inválida, filtro, rede), passa ao próximo. A lista mostra qual modelo escreveu cada história. Antes do lote, o app confere que todos os modelos aceitam imagem.
  • Limite de uso (HTTP 429): espera 5, 15 e 30 s e tenta de novo (Cancel funciona durante a espera).
  • Nível de pensamento: se a resposta vier vazia ou estourar o tempo (3 min), a próxima tentativa pensa um nível a menos, dentro dos níveis que aquele modelo aceita (ex.: Qwen xhigh → medium → low → none; Gemini medium → low). No nível mínimo, passa ao próximo modelo da cadeia. O nível usado fica na coluna writer_effort.

Narração e custo

Modelos Fish Audio no OpenRouter: fish-audio/s2.1-pro-free:free (padrão, grátis, sem garantia de disponibilidade), fish-audio/s2.1-pro, s2-pro e s1 (pagos por uso). O áudio chega em PCM (taxa e canais lidos do cabeçalho) e é salvo em WAV. Custo: modelos :free = 0 na hora; pagos são consultados no OpenRouter em segundo plano logo depois de cada história (as estatísticas levam ~10–15 s) e vão para tts_cost_usd.

Log, falhas, retry e exclusão

  • Status (linha azul): generating… 3/12 done (1 failed) | status: narrating scene 4/6 (Voz) (12 s) — o contador de segundos mostra que o passo está vivo.
  • Já feito é pulado — por estilo: um storyboard que já tem história no estilo selecionado (mesmo conteúdo de imagem) não é refeito — sem custo. Já ter a versão Descritiva não impede gerar a Narrativa (e vice-versa); histórias antigas, de antes dos estilos, contam como Descritivas. Para refazer no mesmo estilo, marque redo existing (refaz todos; cria Título (2), sem apagar a anterior). A coluna storyboards dir mostra de qual pasta veio cada história.
  • Falhas ficam em vermelho com o motivo. Retry failed refaz só as do estilo selecionado; duplo clique ou botão direito numa linha vermelha refaz aquela. O lote continua depois de uma falha; Cancel para tudo e não deixa arquivos pela metade.
  • Botão direito numa linha: Copy row (a linha inteira em texto organizado), Open in Player, Open folder, Delete audio only… e Delete script + audio… (com confirmação, para a Lixeira quando possível; o storyboard original nunca é tocado). O menu fecha ao clicar fora ou com Esc.
  • Ordenar e filtrar: clique no cabeçalho de uma coluna para ordenar (de novo inverte; ▲/▼ indica), respeitando números e datas. Botão direito no cabeçalho abre o filtro estilo planilha: ordenar ▲/▼, “Contains…”, valores com contagem para marcar/desmarcar, All/None, Clear filter. Colunas filtradas ganham ▾; o rodapé mostra “N of M” e o custo só das linhas visíveis; Clear filters volta tudo. A ordenação fica salva; os filtros valem na sessão.
  • Texto que não cabe na coluna aparece inteiro num balão ao parar o mouse sobre a célula; as colunas se ajustam ao conteúdo e há rolagem horizontal.

Pipeline de geração

run_generation() — o coração, usado pelas 3 interfaces:

  1. Monta o prompt final: prompt + arquivos .md/.txt do contexto + instrução de proporção/resolução.
  2. Codifica as imagens de referência (memória) em base64.
  3. Dispara em paralelo: a requisição da imagem e o resumo do prompt (o resumo não atrasa a geração).
  4. Salva as imagens (image_AAAAMMDD_HHMMSS.ext), mede dimensões sem Pillow e acrescenta linhas no CSV com custo.

Lotes com variáveis (Injection) ou com Dynamic rodam uma chamada por geração (run_generation_batch), cada uma com suas pastas; com seed, a geração i usa seed + i − 1. Sem isso, n imagens vão numa chamada só — dividida em blocos de até 10 quando n > 10.

Chaves e cofre

Precedência: flag --api-key > variável de ambiente > cofre local. A chave nunca é impressa nem logada — só um hash curto SHA-256 (16 chars) vai para o CSV.

  • Cofre: ~/.config/image_generate/ — uma chave Fernet (<provedor>.fkey, 0600) + um blob cifrado por provedor (<provedor>_api_key.enc). Precisa de pip install cryptography.
  • Por quê Fernet por provedor? Isola os segredos: apagar/rotacionar a chave de um provedor não afeta o outro.
  • remember me / Forget: salva ou apaga o blob do provedor atual.
  • StoryGenerate usa a mesma chave OpenRouter do cofre (roteirista e narração) — salvar/esquecer em um vale para o outro.

Resumo automático

Cada linha do log precisa de um resumo de 1 frase (≤150 chars). Regra: se summary_model estiver vazio, usa truncamento local sem gastar nada; com modelo, chama o chat em paralelo.

  • Prompt do resumidor endurecido: exatamente 1 frase, no idioma do prompt, e nada além dela (sem thinking, sem preâmbulo), temperatura 0.
  • Sanitização: tira aspas e rótulos (“Summary:”), rejeita vazamento de thinking — rejeitado = fallback para truncamento, o CSV nunca recebe lixo.
  • Privacidade: campos reasoning da resposta são ignorados de propósito (chain-of-thought não entra no log).
  • Dica: use um modelo grátis/pequeno para o resumo — ele não afeta a qualidade da imagem.

Cancelamento

CLI: Ctrl+C. GUI/Web: botão Cancel (a web mostra “cancelling…” enquanto aborta). Semântica garantida: fecha os sockets, apaga arquivos parciais, não loga nada e sinaliza GenerationCancelled. O servidor pode até terminar do lado dele — o resultado é descartado.

Log CSV e custos

log_image_generate.csv na pasta de saída. As 2 primeiras linhas (# …) trazem totais (operações e US$); depois o cabeçalho + 1 linha por imagem: data, resumo, prompt completo, arquivo, bytes, dimensões, resolução/proporção pedidas, custo, timestamps, modelo, provedor e hash da chave.

O painel Summary (GUI) e o histórico da web mostram as requisições da mais nova para a mais velha e se atualizam a cada imagem gerada em lotes (Injection/Dynamic), sem esperar o fim do lote. Com Output Dynamic, os CSVs das subpastas usadas no lote entram na mesma lista (o rodapé indica + N Dynamic log(s)).

ReusoNa web, clicar numa linha do histórico recarrega aquele prompt. No CLI, --list-log despeja o CSV no terminal.
